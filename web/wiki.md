# 驾驶舱使用说明

这份文档解释**每个按钮干什么、数据从哪来、卡住了看哪里**。改 UI 前先看这里，避免再问一次。

## 一、一条任务的生命

```
新建（加入池） → 拆分 → 推入 ─┬─ 任务本体：立刻可开工（CC 干活 / WB 干活看归属）
                    │        └─ 文档那一行：异步队列，WorkBuddy 有空再写
                    └─ 需要 Claude Code 做的，派单给它执行
```

| 阶段 | 在哪块 | 谁在动 | 你怎么知道 |
| --- | --- | --- | --- |
| 预定 | 任务池 | 没人 | 卡片显示「未拆」 |
| 已拆 | 任务池 | 没人 | 显示「已拆 N」 |
| 已推入 | 已推入·任务 | 工作 Agent（默认 CC） | `待派单`，点「执行」即开工；授权打勾则自动开工 |
| 执行中 | 已推入·任务 | Claude Code | `● CC 执行中 · 12s` + 实时日志 |
| 文档同步 | 已推入·任务 | WorkBuddy（异步） | `文档同步排队中 / 写入中 / 失败` |
| 回填 | 已推入·任务 | WorkBuddy | `已回填 done HH:MM` |
| 归档 | 已推入·归档 | — | 池子条目标「已推送」 |

> 重点：推入**不再等** WorkBuddy。任务进队列那一刻工作 Agent 就能开工，腾讯文档那一行由「文档同步队列」异步补写，写完自动回执。

## 二、按钮对照

### 任务池（还没派出去）

| 按钮 | 作用 | 花钱 |
| --- | --- | --- |
| 拆分 | 手写子任务，一行一条；`cc:` 归 Claude Code，`wb:` 归 WorkBuddy | 否 |
| 推入 | 选优先级（高/中/低）后：任务本体立刻可开工（默认派给工作 Agent），文档那一行进异步同步队列 | 否 |
| 删除 | 从池子移除（不影响已生成的任务） | 否 |

### 已推入 · 任务

| 按钮 | 作用 | 花钱 |
| --- | --- | --- |
| 执行 | 用任务备注/提示词派一个新会话给 Claude Code | 是（约 $0.05–0.1） |
| 继续 | 续接上一次会话接着做（它记得上下文） | 是 |
| 智能拆分 | 让 Claude Code 出 3–6 条子任务建议 | 是 |
| 派单提示词 | 把任务说明改写成一条完整派单指令 | 是（约 $0.08） |
| 需求/交付/验收 | 仅公司任务；生成三段文档 | 是 |
| 换目录 | 改这条任务用哪个 WSL 目录 | 否 |
| 终止 | 杀掉正在跑的 Claude Code | 否 |
| 删除 | 从任务表移除 | 否 |
| 优化提示词 | 把输入框里的草稿改写成更好的派单指令，**改完停在框里，你决定推不推** | 是 |

### 等你授权（只在被拒时出现）

Claude Code 想执行但被权限拦住时，这里会出现它想跑的命令 + 建议放行的规则。

- **批准** → 规则记进 `allowlist.json`（以后同类活不再问）+ 自动按原任务重派一次
- **拒绝** → 记 rejected，不重派

## 三、数据从哪来

| 页面元素 | 数据源 | 实时性 |
| --- | --- | --- |
| 任务池 / 任务 / 授权 | `D:\PROJECT\Ds\_progress\*.json` | 5 秒轮询 |
| Claude Code 执行日志 | WSL `/tmp/cc-<id>.stream.jsonl`（stream-json 事件） | 1.5 秒轮询，只在展开时 |
| 正在跑哪条 | `_progress/running.json`（派单开始写、结束删） | 1.5 秒 |
| WorkBuddy 阶段 | `tools/wb-bridge/calls.jsonl`（next_task / report_task 带 taskId） | 5 秒 |
| 今日花费 | `tools/claude-ledger.jsonl` 累加 | 5 秒 |

**关键点：所有信息都能从这几个文件推导出来，不需要进 WSL 看。**

## 三半、文档同步队列（异步）

腾讯文档任务表那一行**不再挡开工**，它是一条独立的异步活：

```
推入 → 任务本体落库（立即可派给工作 Agent）
     └─ 同时 docsync.enqueue()：一条「写主表一行、状态=开发中」的活
          → WorkBuddy 定时来取（MCP 工具 next_docsync），写表格
          → 写完回调（report_docsync / POST /api/docsync/report）
          → 面板显示已同步；失败按 3 次重试，超时 15 分钟自动退回队列
```

- 队列文件：`_progress/docsync.json`
- **回调 done 之后**：任务表里该条打上 `docSyncedAt`，面板上任务卡进度条 `10% → 30%`（台账就绪，等开工），全局阶段条 `② 需求 → ③ 任务表`；没有文档同步要求的任务（WB 自己的文档活）不算卡点。
- 面板接口：`GET /api/docsync`（只读摘要）；回调 `POST /api/docsync/report`（带 `x-dash: 1`）
- MCP 工具：`next_docsync`（取一条，标 running）、`report_docsync`（done / failed）
- **WorkBuddy 侧要建一个 10–30 分钟的定时任务**：`next_docsync` → 有活就写 → `report_docsync`。没建就会一直排队，但**不影响任何任务开工**。

## 四、卡住了先看哪

| 现象 | 先看 | 处理 |
| --- | --- | --- |
| 推入了但一直显示 `文档同步排队中` | WorkBuddy 侧的定时任务建了没 | 去 WorkBuddy 建 10–30 分钟轮询 `next_docsync` |
| 任务推入后一直 `待派单` | 三项确认里的「授权」没打勾（不会自动开工） | 点「执行」，或补打勾再推 |
| 卡片一直「执行中」但日志不动 | `running.json` 是不是残留 | 点「终止」 |
| 派单报错 / 结果为空 | 台账最后一条的 status 和 denials | 看 `claude-ledger.jsonl` |
| 授权队列里有东西 | 命令原文是否合理 | 批准或拒绝，拒绝不会重派 |
| 花费飙升 | 今日花费数字 | 派单脚本默认日上限 $5 |

## 五、命令行等价物

不想点页面时：

```powershell
# 看任务表 / 池子
.\taskboard.ps1 -List

# 派活
.\claude-dispatch.ps1 -Task '<四件套>' -Allow 'Bash(npm run typecheck:*)'

# 花费
.\claude-ledger.ps1 -Query summary

# 起驾驶舱
node .\dashboard\server.mjs     # http://127.0.0.1:8899/app/
```
