## 一句话结论

**终端页不好用，不是样式问题，是「信息在契约层就被拍平了」。** 服务端把 Claude 的 stream-json 一解析就压成 `{kind, text}` 一行行字符串（`server/events.mjs:121-155`），前端再没有任何结构可还原：命令退化成 `$ Bash {"command":"…"}`、一轮对话的「思考 → 动作 → 结果」散成互不相干的行、只保留最后 300 个事件、默认全部收起且不跟随、每 2 秒整包重取。改法是把契约从「行」升级到「轮 + 动作」，前端按动作类型渲染，交互从「卡片堆」换成「会话列表 + 详情两栏」。

## 根因

1. **契约层过早降维**：`stream-json` 本身是结构化事件（assistant 消息 / tool_use / tool_result / result），服务端在 `rawLine()` 里一次性拍平成文本行，丢掉了「谁调用谁」「哪个结果对应哪个动作」「第几轮」。前端再聪明也补不回来。
2. **视角是「日志」不是「动作」**：现在的渲染单位是「行」，人关心的是「它改了哪些文件、跑了哪些命令、哪一步失败」。单位错了，任何美化都是排版问题。
3. **通道是拉取不是推送**：2 秒整包 diff 决定了它是「一跳一跳」的，也决定了做不到逐行流出、做不到滚动跟随、做不到只追加不重排。
4. **回放没有持久化**：唯一数据源在 WSL `/tmp`，而 `data/runs/` 只存回执——「归档」和「回放」是两条不同的路，历史天然会断。

## 设计目标（可验收的定义）

| 维度 | 目标 | 检验方式 |
| --- | --- | --- |
| 清晰 | 打开任意会话，**3 秒内**能回答四件事：它想干什么 / 动了哪些文件 / 哪一步失败 / 跑完没有 | 找一个 20 轮以上的真实会话，计时 |
| 智能 | 不用翻就能看到结论与风险（改了几个文件、几条命令、有没有卡住/循环/连续失败）；证据一键进「标记完成」 | 长会议话是否仍需手抄证据 |
| 方便 | 全程不切页；键盘可达；滚动跟随不打架；长会话能翻到开头 | 全键盘走一遍 |

## 方案总览：一条主线 + 三个阶段

**主线：以「轮（round）」为渲染单位，以「动作（action）」为信息单位。**

- 一轮 = 一条 assistant 消息（thinking / text / 多个 tool_use）+ 紧随其后的 tool_result。
- 一个动作 = 一次工具调用 + 它的结果（按 `tool_use_id` 配对）。
- 会话 = 轮的有序列表；首尾各一个「会话头」与「结束/回执」。

| 阶段 | 交付 | 成本 | 可独立上线 |
| --- | --- | --- | --- |
| **P0 信息成型** | 后端 `readRunRounds()` 契约、工具渲染规则、轮次折叠、跟随、头部摘要 | 约 1 天 | 是 |
| **P1 视图与通道** | 左列表 + 右详情、SSE 增量、搜索与过滤、分段加载 | 约 1.5 天 | 是 |
| **P2 智能层** | 异常提示、摘要进证据预填、动作跳转 | 约 0.5 天 | 是 |

排序理由：P0 不改布局就能消掉「一眼糊」；P1 解决「会话多了不知道看哪条」；P2 必须建立在 P0 的结构化数据上，先做会白做。

## P0 · 契约与信息成型

### 6.1 后端：`readRunRounds(dispatchId)`

新增在 `server/events.mjs`，**不改动** `readRunRaw`（保留旧契约给「复制」和兼容）。

职责边界（明确分给谁）：

- 后端只做**机械活**：按 `tool_use_id` 配对、按 assistant 消息切轮、统计基础计数、标 `truncated`、给稳定 id。
- 前端只做**表达活**：把 `tool + input` 渲染成中文动作（规则函数），拼摘要文案。规则改了不用动后端，也方便单测。

响应形态（`GET /api/task/raw?id=<taskId>&v=2`，同端点加版本参数，避免新增路由）：

```json
{
  "dispatch": "20261113-162451-1a36dd",
  "running": false,
  "source": "archive",
  "truncated": false,
  "stats": { "rounds": 5, "tools": 12, "errors": 1, "turns": 5, "durationMs": 15102, "cost": 0.1298 },
  "rounds": [
    {
      "i": 1,
      "at": "16:24:51",
      "durMs": 1200,
      "status": "ok",
      "think": "先读 AGENTS.md 和 docs/agent-rules.md…",
      "say": "",
      "actions": [
        {
          "id": "toolu_01",
          "tool": "Read",
          "input": { "file_path": "/home/jz/Vesta/AGENTS.md" },
          "ok": true,
          "ms": 41,
          "out": "…",
          "err": null
        }
      ]
    }
  ],
  "end": { "status": "ok", "result": "…", "durationMs": 15102 },
  "lines": [ … ]
}
```

规则：

- `source`：`archive`（`data/streams/<id>.jsonl`）→ `wsl`（`/tmp/cc-<id>.stream.jsonl`）→ `missing`。三者都试，`missing` 时前端必须显式提示，不许空白。
- `input` 保留完整入参；`out` 每条例 4000 字（不再是 800）。
- **必须按轮分页**：实测单条流最大 11.7 MB，整包读会同时卡住 Node 与浏览器。默认返回最后 40 轮；`?before=<round.i>` 往前翻；响应带 `{ truncated, hasMore, totalRounds }`。单响应上限 2 MB。
- 读文件不要 `readFileSync` 整读后全量 JSON 解析：按行流读（`createReadStream` + `readline`），只解析窗口内的行。
- 稳定 id：`round.i` 与 `action.id`（`tool_use_id`）进 DOM key，替换现在的 `:key="i"`（`TerminalCard.vue:52`），为 P1 的增量追加打底。
- 新增 `GET /api/task/stream?id=<taskId>`：直接下载原始 `jsonl`，供「下载原始日志」与排查，不做任何解析。

### 6.2 回放持久化（顺手补的洞）

派单结束时把 `\\wsl.localhost\<DISTRO>\tmp\cc-<id>.stream.jsonl` 复制到 `data/streams/<id>.jsonl`：

- 触发点：`server/dispatch.mjs:81-99` 的子进程 `close` 回调里、`resolve` 之前（失败也复制，`rc != 0` 的流最有排查价值）；派单脚本本来就带 `-Stream`（`dispatch.mjs:60`），流文件一定存在。
- `paths.mjs` 加 `streamsDir`；`server.mjs:277-309` 的 `historyStats` / `purgeHistory` 一并统计与清理（沿用现有「清 N 小时」语义，`/api/maintenance/purge` 自动带上）。
- 体积预估（实测校准）：现存 15 条流 18.3 MB，平均 1.2 MB/条；按 34 条估**约 40 MB**（另有极值 11.7 MB 的单条）。按天保留 7 天即可，或只保留任务表仍在引用的会话（待确认 #3）。

### 6.3 前端：工具渲染规则

新建 `web/src/utils/terminal.ts`，纯函数，输入 `{ tool, input, ok }`，输出展示模型。**未知工具一律降级为原始名 + JSON 折叠**，不猜。

| 工具 | 动作名 | 目标 | 尾部信息 | 默认 |
| --- | --- | --- | --- | --- |
| `Bash` | `$` | `input.command`（原文，不套 JSON） | 退出码 / 错误 | 展开前 5 行输出 |
| `Read` | `读` | `basename(file_path)` | 行数（从 `out` 数） | 折叠 |
| `Write` | `写` | `basename(file_path)` | `+n 行` | 展开 |
| `Edit` / `MultiEdit` | `改` | `basename(file_path)` | `+a −b`（由 `old_string`/`new_string` 行数差算） | 展开 |
| `Grep` | `搜` | `input.pattern` | 命中数 | 折叠 |
| `Glob` | `找` | `input.pattern` | 文件数 | 折叠 |
| `TodoWrite` | `待办` | — | `n 项变更` | 折叠 |
| `WebFetch` / `WebSearch` | `网` | URL / 查询词 | — | 折叠 |
| `Task` / `Agent` | `子任务` | `input.description` | — | 折叠 |
| 其他 | `⚙ name` | 入参首行截断 | — | 折叠 |

同时废弃「思考/输出/命令同权重」的视觉：`think` 弱化为灰色斜体块（保留），`cmd` 变成「动作行」（等宽 + 图标 + 目标），`err` 行加左侧红条。

### 6.4 前端：轮次折叠

```
第 3 轮 · 3 动作 · 2 文件 · 41s            ← 空状态折叠成这一行
  ├ $ npm run verify
  ├ ✏ 改 server.mjs +12 −3
  └ 读 docs/api.md
```

- 默认：**只展开最后一轮**，其余折叠成一行摘要；完成态会话默认展开最后一轮 + 收尾回执。
- 含错误的轮：默认展开，且摘要行右侧挂红点。
- 「展开全部 / 收起全部」放会话头。

### 6.5 前端：跟随与摘要

- 默认贴底跟随；用户上翻（距底 > 48px）→ 暂停跟随，右下角显示「↓ N 条新输出」，点它或滚回底部自动恢复。
- 会话头摘要：`3 文件 · 12 动作 · 1 错`（错误非零时红字），替换现在的「N 行」（`TerminalCard.vue:34`）。
- 空态分三种：跑着但还没输出（已有）、`source === "missing"`（新增：「这次的流已不在（WSL /tmp 已清），只能看回执」+ 回执内容）、真的没有会话。

- 两栏 `grid-template-columns: 320px minmax(0, 1fr)`；`<900px` 折回单栏（列表在上，点进详情）。
- 列表项：状态点（跑/错/完成）、`#id`、标题、时长、错误红点。**不再 slice(0, 8)**，全量列表 + 简单筛选。
- 全屏沿用现有 `fullTerm` 机制（fixed inset + backdrop），只是把容器从卡片换成详情栏。
- 右侧授权栏（`AuthRail.vue`）保持现状，随详情栏固定。

### 6.7 通道：SSE 增量

服务端 `streamClaude` 已经写好（`server/events.mjs:174-219`，700 ms tick，连上先补发尾部 40 条），但仓库里**没有任何前端在消费**（全仓 grep `events/claude`、`EventSource` 只有 WorkBuddy 那条）。

做法：

- `/events/claude?taskId=<id>`：事件带 `taskId`，前端按 id 过滤；断线自动重连（浏览器原生）。
- 只对**选中的会话**开流；列表状态仍走 `/api/state` 5 秒轮询。
- 跑完（收到 `done`）关流，再发一次 `?v=2` 的 GET 收尾，保证与服务端结构完全一致。
- 失败降级：SSE 建连失败 → 回到 2 秒轮询，UI 不报错。
- 视图形同 `v-show` 或 `<KeepAlive>`，切页回来滚动位置与展开态不丢（现状是 `v-if`，DOM 重建后滚回顶部，见 5 号文档 5.3）。

### 6.8 交互：搜索、过滤、键盘

- 顶部搜索框：按「命令文本 / 文件路径 / 输出内容」过滤，命中高亮，`Enter` 跳到下一个。
- 过滤 chip：`只看改动`（Edit/Write/Bash 中非只读命令）、`只看错误`（`ok === false` 或 `kind === "err"`）、`只看命令`。
- 键盘：`/` 聚焦搜索、`j`/`k` 切会话、`f` 全屏、`Esc` 关闭搜索/全屏、`Enter` 展开当前轮。
- 「下载原始日志」→ `/api/task/stream?id=`。

## P2 · 智能层（规则实现，不接模型）

### 6.9 会话摘要

由 `utils/terminal.ts` 从 rounds 计算，**纯函数、可单测、不依赖网络**：

```
改了 3 个文件（AGENTS.md、docs/api.md、server.mjs）· 12 个动作 · 1 个错误（Edit: old_string 未命中）· 5 轮 · $0.13
```

### 6.10 异常提示

| 规则 | 阈值 | 文案 |
| --- | --- | --- |
| 长时间无新事件 | 跑着且 > 90 s 无新增 | 「已 90 秒没有新输出，可能在等授权 / 卡住」 |
| 重复命令 | 同一 `Bash.command` 出现 ≥ 3 次 | 「同一条命令重复了 3 次，可能在绕圈」 |
| 连续失败 | 连续 2 个动作 `ok === false` | 「连续 2 个动作失败」 |

提示挂在会话列表项与详情头，点击跳到对应轮。

### 6.11 证据预填

`utils/format.ts:49` 的 `buildEvidence` 现在只拼「状态 · N 轮 · $花费 + result 截 600」。P2 起改为：

```
ok · 5 轮 · $0.130 · 改了 3 个文件 · 1 个错误
<result 摘要，600 字内>
```

`useTasks.ts:216-223` 的 `openMark` 直接复用，不再需人手抄。

## 不做的事（避免过度设计）

- **不引 xterm.js**：这不是真 TTY，是结构化回放，终端模拟器会把结构化信息重新压回字符流。
- **不引 Pinia**：现有 composable 够用（与 5 号文档一致）。
- **不引组件库**：单色极简是刻意设计，`style.css` 已统一。
- **不做虚拟滚动**（P1 先分段加载）：会话上限 8→全量列表，但单条会话按轮分页即可。
- **不用 LLM 做摘要**：成本、延迟、不可复现；规则摘要足够，且能进单测。
- **不动派单链路**：异步派单、状态轮询归 5 号文档（5.1 / 5.2），本文只管「看到的东西」。

## 验收标准

**P0**

- `Bash` 显示为 `$ npm run verify` 本体；`Edit` 显示为 `✏ 改 server.mjs +12 −3`；未知工具显式降级。

- 会话头显示「N 文件 · N 动作 · N 错」，错误数非零时红字。
- 旧 `lines` 字段仍在，「复制」行为不变（回归）。
- 20 轮以上的会话能看到第 1 轮（不再被 300 截断）。

**P1**

- 左列表右详情；列表显示状态点、时长、错误红点；超过 8 条也能看到。

- 全键盘可完成：切会话 → 搜索 → 展开 → 全屏 → 关闭。

**P2**

**通用**
